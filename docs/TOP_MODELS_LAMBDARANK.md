# MovieLens 32M — top-model LambdaRank experiment

The goal is to test **whether ranking scores from your best already-trained
recommendation models can improve NDCG@10 with LightGBM LambdaRank**.

The controlled ablation compares frozen scores, simple score fusion,
one-score LambdaRank rerankers, and a stacked LambdaRank reranker. It
**does not** fabricate performance numbers or silently load unsupported
research-patch checkpoints.

## Candidate models

Priority research roster:

1. `hofm4_jointbcd` — your fourth-order + JointBCD research branch
2. `hofm3_semi25_jointbcd` — the strong third-order + temporal JointBCD model
3. `bpr` — collaborative BPR baseline
4. `temporal_fm` — temporal collaborative/context baseline
5. `deepfm` — optional DeepFM
6. `semantic` — optional title/genre/tag similarity
7. `svd` / `popularity` — optional classical benchmarks

**Names are not claims of trained availability.** Your ML32M HOFM3 and
HOFM4 models are Codespace-local research-patch implementations, and this
repository does not yet offer a supported generic inference API for their
checkpoints. The full-catalog sentence vectors are *features*, not
per-query personalized ranker predictions until a historical user-profile
scorer produces actual query/movie scores.

Use any **2 or more frozen models that have real scores on identical
candidates**. By default the script picks the **4 highest frozen validation
NDCG@10** scores, not the 4 names it happens to like. You can force
specific models via `--models`.

## 1. Export the candidate pools and frozen base-model scores

Required local files (CSV or Parquet):

```text
artifacts/rerank/train.csv
artifacts/rerank/valid.csv
artifacts/rerank/test.csv
artifacts/rerank/evaluation_manifest.json
```

Example row structure — **illustrative schema, not a real model prediction**:

```text
query_id,item_id,label,total_relevant,score_hofm4_jointbcd,score_hofm3_semi25_jointbcd,score_bpr,score_temporal_fm,feature_historical_popularity
```

The score tables for all three splits must have identical feature names
and comparable model checkpoints. Each query corresponds to a
recommendation event, e.g. `user_id + historical_timestamp + split`, and
each row is an eligible candidate movie.

**Use your existing chronological MovieLens 32M evaluation split.** Do
not split randomly, mix future tags into features, or tune HOFM models on
the ranker-training positives. All score sources must be generated by
models frozen **before** the ranker supervision or from out-of-fold
training predictions. User history must be strictly earlier than each
query timestamp.

A good starting candidate pool is **500–1000 movies per query** from a
union of the base retrievers plus additional sampled competitors,
provided every experiment uses *exactly the same* pool. Set
`total_relevant` to the **actual held-out relevant count** for every
query, including queries in which retrieval missed all positives.

**Do not call Recall@500 or full-catalog NDCG unless the pool and its
construction genuinely justify those names.** If the original 0.13
NDCG@10 came from a different candidate policy, its value cannot be
compared directly to this experiment.

If models export independent prediction files, assemble each split using
the existing exact-match joiner:

```bash
python -m src.lambdarank_rerank join \
  --base artifacts/rerank/train_base.csv \
  --score hofm4_jointbcd=artifacts/rerank/train_hofm4.csv \
  --score hofm3_semi25_jointbcd=artifacts/rerank/train_hofm3.csv \
  --score bpr=artifacts/rerank/train_bpr.csv \
  --score temporal_fm=artifacts/rerank/train_temporal_fm.csv \
  --output artifacts/rerank/train.csv
```

Run analogous join commands for `valid.csv` and `test.csv`. Each
`train_hofm3.csv` etc. must contain **exactly**
`query_id,item_id,score`, keyed to all the base candidates.

The manifest must contain the actual dataset and protocol fields and
three explicit provenance attestations (see
[LambdaRank reranking guide](LAMBDARANK_RERANKING.md)).
A manifest is not a substitute for checking your source code's
historical data availability.

## 2. Audit — no training, no database

```bash
cd /workspaces/Reco
python -m src.lambdarank_top_models audit
```

This reads the manifest and all three candidate files, checks finite
scores, split-disjoint query IDs, score-schema equality, the presence of
positive and unlabeled ranker training examples, and records SHA256
fingerprints of each input. It reports real frozen validation NDCG@10
for every available score column and the selected top four.

If inputs are missing, it **stops explicitly** rather than hallucinating
pretrained model scores.

Specify models explicitly if all are available:

```bash
python -m src.lambdarank_top_models audit \
  --models hofm4_jointbcd,hofm3_semi25_jointbcd,bpr,temporal_fm
```

## 3. Run the experiment (new, non-overwriting directory)

```bash
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 OPENBLAS_NUM_THREADS=1 \
python -u -m src.lambdarank_top_models run \
  --models hofm4_jointbcd,hofm3_semi25_jointbcd,bpr,temporal_fm \
  --k 10 \
  --trees 300 --early-stop 30 \
  --leaves 15 --min-leaf 20 --lr 0.03 --l2 10 \
  --threads 4 --seed 42 \
  --bootstrap 1000 \
  --output artifacts/rerank/top_models_v1
```

If some scores are not available, omit `--models` to use the best **up to
four available** frozen models according to validation NDCG.
Start with `--dry-run` to inspect selected models and input SHA256s
before training. If output `top_models_v1` exists, **do not delete it**;
use a new run name such as `top_models_v2`.

The driver invokes the existing, tested LightGBM LambdaRank implementation
once for every selected single-model experiment plus an ensemble trained
on all selected score columns and shared historical `feature_*` fields.

Models are **ranked for selection on validation only**. The held-out test
does not decide which result is the official champion.

## 4. Ablation matrix

| Variant | Model features | Purpose |
| --- | --- | --- |
| Frozen BPR / HOFM3 / HOFM4 / temporal FM | One original score | Honest baselines |
| `zmean` | Per-query standardized mean of selected score columns | Untrained linear score fusion |
| `rrf` | Reciprocal rank fusion of selected scores (constant 60) | Untrained rank fusion |
| Single-model LambdaRank | One model score + optional past-only metadata | Learn nonlinear corrections |
| Stacked LambdaRank | All selected model scores + optional past-only metadata | Joint model complementary signals |

Score fusion does not learn weights on the test set. LambdaRank trains on
ranker-training queries and early-stops using validation NDCG; the same
LightGBM config is used across variants.

## 5. Actual outputs — JSON-first Reco Studio

```text
artifacts/rerank/top_models_v1/
    summary.json                         # Existing reranker summary
    top_models_analysis.json             # Comparisons, selected champion, CIs
    report_baseline_<model>.json         # Each real frozen test score
    report_lambdarank_<model>.json       # Each real reranker test score
    report_lambdarank_ensemble.json      # Combined model test score
    lambdarank_<model>.txt               # Trained native LightGBM booster
    lambdarank_ensemble.txt
    predictions_<model>.csv
    predictions_ensemble.csv
```

Output `top_models_analysis.json` includes:
- Dataset and exact protocol and score-source SHA256s.
- Frozen-model ranking on validation, selection and candidate counts.
- Validation and test NDCG@10/Recall@10/Hit Rate@10 for each variant.
- Champion selected **only by validation NDCG**.
- The test NDCG difference from the **best frozen validation baseline**.
- A paired query-bootstrap 95% confidence interval (queries from the same
  user may be correlated; this interval is **not** user-cluster robust).

The Reco Studio JSON explorer and Model comparisons display the reranker
report files in this directory. No SQLite database is needed and the
optional old registry is **not** written.

```bash
streamlit run app.py --server.address 0.0.0.0 --server.port 8501
```

## 6. Important limitations

- The driver **does not calculate the base model scores directly from the
  Codespace checkpoints**. It needs genuine point-in-time score exports.
- A stronger reranker can't recover a relevant movie excluded by the
  initial retrieval stage.
- Selecting a model on a validation split means its validation performance
  is optimistic. Compare your selected champion on a pristine test set.
- Per-query paired bootstrap estimates exclude uncertainty from selecting
  base models and hyperparameters, and are not cluster-robust when one
  user generates many queries.
- If a user wants to investigate `lambdarank` vs `rank_xendcg`, use
  an independent prespecified follow-up ablation, not test-set cherry-picking.

### Regression tests

```bash
python -m pytest -q tests/test_lambdarank_top_models.py
```

A synthetic MovieLens-style test performs **actual LightGBM training**,
checks that summary and JSON reports exist, and confirms no SQLite database
was created. It is not a real MovieLens benchmark and does not represent
the trained performance of the advanced research models.
